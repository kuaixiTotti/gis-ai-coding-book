## 对话 1:从零创建第一张地图

### 背景

项目初始化阶段,我希望从零做出第一个能在浏览器里打开的 Leaflet 地图。
本次对话约 5 分钟,1 轮就成功。

### 完整对话

> 👤 你是一个熟悉 Leaflet 的前端工程师。
>
> 帮我创建一个单文件 HTML,用 Leaflet 显示一张地图,初始视野在北京大学(经纬度约 116.308, 39.995),缩放级别 15。
>
> 约束:
> - Leaflet 通过 CDN 引入,不要 npm
> - 底图用 OpenStreetMap
> - 页面打开地图要占满整个屏幕
> - 代码要有中文注释,适合初学者
>
> 输出单个 index.html 文件。

> 🤖 这是一个完整的单文件 HTML,你保存为 `index.html` 用浏览器打开即可:
>
> ```html
> <!DOCTYPE html>
> <html lang="zh-CN">
> <head>
>   <meta charset="UTF-8">
>   <title>我的第一张 Leaflet 地图</title>
>   <link rel="stylesheet" href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css">
>   <style>
>     html, body { margin: 0; padding: 0; height: 100%; }
>     #map { width: 100%; height: 100%; }
>   </style>
> </head>
> <body>
>   <div id="map"></div>
>   <script src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js"></script>
>   <script>
>     // 创建地图,setView([纬度, 经度], 缩放级别)
>     const map = L.map('map').setView([39.995, 116.308], 15);
>
>     // 添加 OSM 底图
>     L.tileLayer('https://tile.openstreetmap.org/{z}/{x}/{y}.png', {
>       attribution: '© OpenStreetMap contributors',
>       maxZoom: 19
>     }).addTo(map);
>   </script>
> </body>
> </html>
> ```
>
> 几个关键点:
>
> 1. Leaflet 的 CSS 必须在 JS 之前加载
> 2. `#map` 容器**必须有明确的高度**,这里我用 `html, body { height: 100%; }` + `#map { height: 100%; }` 让它占满全屏
> 3. `setView` 接收 `[lat, lng]`(纬度在前!和 GeoJSON 的 [lng, lat] 相反)

### 关键时刻

- 🟢 **第 1 轮:AI 主动提示"setView 的纬度在前,和 GeoJSON 相反"**——这是 Leaflet 的经典坑,AI 没等我问就主动指出来了。这种"超出问题本身的警示"是好 AI 的标志。

### 复盘

这是一次理想的"一发命中"。原因:

1. Prompt 五要素齐全(角色、任务、约束、数据隐含、输出明确)
2. 任务足够小,没有歧义
3. 约束里"代码要有中文注释,适合初学者"对结果质量影响很大——没有这一条 AI 会给一段没注释的代码

教训:**这种小任务不要害羞,直接用完整 Prompt 框架**。看起来"杀鸡用牛刀",但写下来不超过 1 分钟,换来的产出质量值得。

## 对话 2:静默失败的调试

### 背景

加完 GeoJSON 数据后,刷新页面发现底图正常,但点没显示。这是前端开发最讨厌的场景:**没有报错的错误**。

本次对话演示如何用 AI 排查这种问题。约 8 分钟解决。

### 完整对话

> 👤 我加载了 data/campus.geojson 但是地图上没有点显示。底图正常,Console 我没看出明显错误。该怎么排查?

> 🤖 "没有明显错误"通常意味着错误被吞了。我建议按这个顺序检查:
>
> 1. **打开 Console**(F12)再仔细看一次,特别注意红色和黄色信息。是否有任何 fetch 相关的失败?
> 2. **打开 Network 面板**,过滤 XHR / Fetch,看 GeoJSON 请求是否成功(状态码 200?404?)
> 3. **检查 fetch 的 URL 路径**是否正确(注意大小写、注意 `.geojson` 不是 `.json`)
>
> 你可以贴一下 Console 的内容,以及你的 fetch 代码吗?

> 👤 看到了 Console 里有一条之前没注意的:
>
> ```
> GET http://localhost:8000/data/campus.json 404 (Not Found)
> ```
>
> 我的代码是 `fetch('data/campus.json')`。
>
> 我的文件名是 `campus.geojson`。

> 🤖 找到了!**路径里漏了 `geo`**。
>
> 改成:
>
> ```javascript
> fetch('data/campus.geojson')
> ```
>
> 改完刷新页面就好。
>
> 顺便提醒一下:类似的"静默失败"以后会经常遇到,养成习惯——
> **页面不对劲时立刻打开 DevTools 检查 Console 和 Network**。
> 这一步要变成肌肉记忆。

> 👤 改完确实好了。这种问题以后我应该怎么避免?

> 🤖 几个习惯能极大降低这类问题:
>
> 1. **fetch 一律加 .catch**:
>    ```javascript
>    fetch(url)
>      .then(r => r.json())
>      .catch(err => console.error('加载失败:', err));
>    ```
>    虽然 Network 面板能看到 404,但显式 catch 会让错误**也出现在 Console**,更难漏掉。
>
> 2. **fetch 之前 console.log 出 URL**:在开发阶段,往 fetch 上面加一行 `console.log('fetching:', url)`,你会立刻看到拼写错误。
>
> 3. **用 IDE 的"自动补全"**:Cursor 在你打 `fetch('data/c'` 时会提示已存在的文件,选自动补全的值就不会拼错。

### 关键时刻

- 🟢 **第 1 轮**:AI 没有直接猜答案,而是给我一个**排查流程**。这正是初学者最需要学的——**调试不是猜,是流程**。
- 🟢 **第 3 轮**:AI 主动总结"以后怎么避免",超出了我的提问。这种"教训沉淀"对长期成长极有价值。
- 🟡 **第 1 轮我应该追问**:"这种'静默失败'的本质是什么?为什么不报错?"——会得到关于 fetch + Promise 错误传播机制的解释,值得记录。

### 复盘

这次对话的价值远超"修一个 bug"。我学到的:

- **排查流程**(Console → Network → 路径)
- **防御性编程习惯**(catch、log、IDE 辅助)
- **"静默失败"作为一个概念**——之前我只觉得是个具体问题,现在意识到这是一类常见现象

**把这种对话存档,胜过看十篇文章**。这就是为什么本书强调"积累自己的对话库"。

## 对话 3:让 AI 帮我自检 Prompt

### 背景

在做完整个项目后,我想反思一下哪些 Prompt 写得不够好。
这一次的对话不是为了产出代码,而是为了**让 AI 帮我做元层面的反思**。

### 完整对话

> 👤 我用以下 Prompt 完成了一个 Leaflet 校园地图项目:
>
> 1. 创建第一张地图(单文件 HTML、北大、OSM 底图)
> 2. 加底图切换控件
> 3. 加载 GeoJSON 并标记
> 4. 按类别着色
> 5. 加图例
> 6. 鼠标悬停交互
>
> 整个过程基本顺利,但有些地方反复了。
>
> 请帮我审视一下:**哪些 Prompt 写得不够好?**
> 如果让我重做一次这个项目,Prompt 应该怎么改?

> 🤖 我推测一下你可能遇到的反复(基于这类项目的常见情况):
>
> **Prompt 3(加载 GeoJSON)**可能反复了 1-2 次,常见原因:
>
> - 你没说清 GeoJSON 的字段结构,AI 默认假设字段名,你的实际字段不同
> - 你没说要不要绑定 popup,AI 默认绑了或没绑都可能不符合期望
>
> **改进建议**:
> ```
> 在 index.html 里加载 data/campus.geojson,假设其结构如下:
> {
>   "type": "FeatureCollection",
>   "features": [{
>     "type": "Feature",
>     "properties": { "name": "未名湖", "category": "景观", "desc": "..." },
>     "geometry": { "type": "Point", "coordinates": [116.31, 39.99] }
>   }, ...]
> }
>
> 把每个点绘制为标记,点击时弹出 popup 显示 name/category/desc。
> ```
>
> ---
>
> **Prompt 4(分类着色)**可能反复,常见原因:
>
> - 你没指定颜色,AI 选了不喜欢的颜色,你又让它改
> - 你没说边框、半径,AI 给的标记可能太大或太小
>
> **改进建议**:用第一次就提供颜色十六进制值、半径、边框宽度这些视觉参数,
> 而不是先让 AI"试试看"再调。
>
> ---
>
> **Prompt 6(悬停交互)**可能反复,常见原因:
>
> - 没说"恢复原状",AI 可能只写了 mouseover 没写 mouseout
> - tooltip 位置没指定,可能挡住 popup
>
> **改进建议**:任何成对的事件(进/出、显/隐),**在 Prompt 里都要双方都写**。

> 👤 你说得很准。Prompt 4 我改了三轮才得到想要的颜色。
>
> 还有一件事:整个过程里,我应该在哪一步加上"代码审查"?

> 🤖 推荐两个时机:
>
> **第一个时机:Prompt 3 完成后**(数据加载流程跑通)。
>
> 因为 fetch + Promise 链条容易出错,这时候做一次审查能发现:
> - 错误处理是否齐全(404 怎么办?json 解析失败怎么办?)
> - 内存泄漏(地图实例销毁时图层有没有清掉)
> - 边界情况(空数据、坐标无效)
>
> **第二个时机:Prompt 6 完成后**(项目主体完工)。
>
> 这时候应该问 AI:
> - 整体代码结构合理吗?有没有可以抽函数的重复?
> - 性能上有没有明显问题?
> - 如果数据量从 5 个变成 5000 个,哪里会卡?
>
> 第二轮审查的产出,**就是你下一个版本的需求列表**。

### 关键时刻

- 🟢 **整段对话**:AI 在做一件超出"代码生成器"的事——**反思我的工作流**。这是 AI 价值的一个被低估的维度。

### 复盘

这次对话给我的最大收获:**AI 不只是写代码工具,也是工作方式的镜子**。

定期(比如每完成一个项目)做一次这样的元层面对话,等于免费请了一位资深工程师做 1v1 复盘。建议把这种对话作为习惯,**每月做一次**。

## 模板使用说明

如果你要为自己的项目记录对话:

1. 用三档颜色标注(🟢 好、🟡 可改进、🔴 错误)
2. 每段对话后写一段"复盘"——这是真正提升你能力的部分
3. 对话脱敏,确保不暴露 token、密码、未公开数据
4. 文件名按项目命名,放到 `dialogues/<chapter>/<topic>.md`

记住:**对话本身不值钱,反思值钱**。
