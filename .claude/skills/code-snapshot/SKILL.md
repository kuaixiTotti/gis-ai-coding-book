# 代码分步快照

把 `code/chXX-*/` 项目的当前代码存为一个 `steps/` 快照。

> 📌 为什么重要:`steps/` 是核心教学资产——每个子目录都是**独立可运行**的版本,学生跳着用。加新功能时必须留快照,而不只是更新 `final/`。

## 第一步:确认目标项目与步骤

- 确认是哪个 `code/chXX-<slug>/` 项目。
- 看 `steps/` 现有子目录,确定下一个步骤号。命名:`step-NN-<slug>`(两位数 + kebab-case 描述,如 `step-03-geojson`)。
- 最终版固定叫 `steps/final/`。
- 向用户确认这一步的 slug 和"这一步新增了什么"。

## 第二步:确定快照内容来源

问清当前可运行代码在哪:
- 通常在项目的 `src/` 或 `final/`,或用户正在改的工作副本。
- 快照是**完整可运行版本**,不是 diff——把该步骤运行所需的全部文件(代码、必要的 `data/`、最小 README)都放进 `steps/step-NN-<slug>/`。

## 第三步:创建快照

1. 创建 `steps/step-NN-<slug>/`。
2. 复制当前可运行代码进去。每个快照必须能独立跑起来。
3. 在快照目录放一个简短 `README.md`(或在文件顶部注释)说明:这一步实现了什么、怎么运行、与上一步的关键差异。

## 第四步:自检

- 确认快照能独立运行(不依赖其它 step 目录的文件)。无法亲自运行时,明确告诉用户"未实测,请跑一遍确认"。
- 相邻 step 的 diff 宜在 30–80 行(README 学习路径假设单步 5–10 分钟读完)。diff 过大 → 建议拆成两个 step。
- 更新项目根 `README.md` 的"项目结构"里 `steps/` 列表。

## 收尾

- 代码注释密度按 style-guide §2.4 随章节阶段递减;注释解释"为什么"。
- 建议提交:`feat(chXX): 新增 step-NN-<slug> 代码快照`。
