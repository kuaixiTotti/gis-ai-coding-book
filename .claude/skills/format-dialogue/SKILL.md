# 整理 AI 对话记录

把一段真实 AI 对话整理成本书的标准格式。对话记录是本书核心教学资产。

> 📌 铁律:**对话必须真实发生过,绝不编造。** 只整理格式,不补写、不润色对话内容本身。若用户提供的对话不完整,如实保留,不要脑补。

## 第一步:脱敏(最先做,不可跳过)

扫描对话全文,**移除或替换**:

- 邮箱、API token、密钥、密码
- 真实姓名、手机号、身份证号
- 未公开的数据源地址、内网 URL、服务器 IP
- 截图路径里可能泄露的用户名

替换为占位符(`<your-token>`、`同学 A`)。脱敏后向用户列出改了哪些地方,请其确认。

## 第二步:判断该用哪种格式

### 短对话 → 段内引用块(style-guide §3.1)

只有一两轮、直接嵌进正文的,用引用块:

```markdown
> 👤 这段代码报错怎么办?
>
> 🤖 看起来是坐标系不一致,建议先用 `to_crs` 转换一下。
```

### 完整对话 → 独立文件(style-guide §3.2)

多轮、有教学价值的完整片段,存独立文件:

- 路径:`dialogues/chXX/<topic-slug>.md`(topic 用 kebab-case)
- 章节配套代码项目下的精选对话另放 `code/chXX-*/DIALOGUE.md`

文件模板:

```markdown
# <对话标题>

## 背景

[2-3 句话说明这次对话的目标和上下文]

## 完整对话

> 👤 [用户消息]

> 🤖 [AI 回复]

> 👤 [追问]

> 🤖 [回复]

## 关键时刻

- 🟢 第 N 轮:AI 主动指出我没考虑到的边界情况
- 🟡 第 N 轮:这里我应该追问但没问
- 🔴 第 N 轮:AI 给出了错误的 EPSG 代码,跑了才发现

## 复盘

[200-300 字反思:这次对话哪里做对了、哪里可以更好]
```

## 第三步:填"关键时刻"与"复盘"

- 🟢 做得好的点 / 🟡 本可更好 / 🔴 AI 出错或误导——只标对话里**真实出现**的,没有就留少几条。
- 复盘 200–300 字,第二人称口吻,与全书文风一致(见 style-guide §1)。
- 复盘可由用户写;AI 协助起草时必须基于对话实际内容,不拔高、不虚构教训。

## 收尾

- 若新建了 `dialogues/chXX/`,确认目录存在(可由 new-chapter skill 预建)。
- 建议提交:`docs(chXX): 新增对话记录 <topic>`。
