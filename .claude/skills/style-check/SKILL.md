# 风格规范快速检查

对指定的章节 Markdown 文件(默认 `book/chXX-*/chXX-*.md`)逐条核查 `style-guide.md` 里**可机械判定**的硬规则,输出问题清单。不改文风、不做主观判断——那是 style-reviewer agent 的事。

## 检查项

逐条扫描,命中即报告(给出行号与原文)。

### 1. 中英文混排空格(style-guide §1.2)
- 中文与英文/数字之间应有半角空格:`使用 Leaflet`✓ / `使用Leaflet`✗
- 中文与中文标点之间**不加**空格
- 中文与英文标点之间**不加**空格

### 2. 段落与小节长度(§1.1)
- 每段正文 > 5 句话 → 报"建议拆段"
- 每节正文(不含代码块)> 1500 字 → 报"建议拆节"

### 3. 禁用词(§1.4 + §8)
扫描并报告:`显然`、`易得`、`众所周知`、`不难发现`、`显而易见`、`我们将会看到`、`在这种情况下`、`通过……我们可以`。

### 4. 段落标记符号(§1.5)
- 只允许 `> 💡` `> 📌` `> ⚠️` `> 💬`
- 同一段叠用多个符号 → 报错(一段只用一种)

### 5. 术语表一致性(§6)
对照术语表,报告不规范写法:
- `AI 编程`/`AI 辅助编程`(本书语境应为 `AI 对话式编程`)
- `Geo JSON`/`geojson`(应为 `GeoJSON`)
- `特征`(指 feature 时应为 `要素`)
- `投影系`(非真指投影时应为 `坐标系`)
- `WGS84`/`GCJ-02`/`CGCS2000` 是否大写、是否误加空格
- `层`(歧义,应为 `图层`)、`背景图`(应为 `底图`)
- 指 Git 时 `项目`(应为 `仓库`)、`推送` 与 `提交` 是否混用

### 6. 章节结构完整性(§5 + writing-guide)
确认本章是否含齐:学习目标(3–5 条)、开场引子、小结、延伸阅读、习题(2 基础 + 2 进阶 + 1 挑战)。缺哪项报哪项。

### 7. 钩子回收(§8.6)
统计"后续章节会讲"/"下一章会讲"/"以后会讲"类表述,> 3 次则报告。

### 8. 代码块规范(§2)
- Python 代码块:变量名是否英文、注释是否中文、是否有"复述代码"的注释
- 反例代码块上方是否有 `⚠️ 反例` 标注
- 命令行提示符是否统一用 `$`

## 输出格式

按严重度分组,每条给 `文件:行号` + 问题 + 建议改法:

```
## 风格检查报告:book/ch05-poi-platform/ch05-poi-platform.md

### 必须修正(违反硬规则)
- L42 中英文未加空格:"使用Leaflet" → "使用 Leaflet"
- L88 禁用词:"显然" → 直接陈述或删除

### 建议修正
- L120 段落超过 5 句话,建议拆为两段
- §5.3 正文约 1720 字,超过 1500 字上限

### 结构提醒
- 未发现"延伸阅读"小节
```

只读不改。修正交给用户确认,或用户明确说"按报告改"时再动手。
